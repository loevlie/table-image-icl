A table where every row has a photo

Three context rows carry a label. The test row does not. Each photo is cut into patches, here two; each patch is a vector of four numbers, drawn as a 2×2 grid. Hover a photo to read its vectors.

The read

Each patch of the reader asks the patches of its k neighbours: queries and keys are patch content. What comes back is not content: the value of a neighbour patch is its photo's label embedding. So a patch reads a weighted mix of labels, a soft nearest-neighbour vote.

No cheating

What the stage receives:

  • h the patch tokens of every row, context and test
  • y_context the labels of the context rows,
  • E the label table: e0, e1, e2
  • y_test not an input

Then what

  1. What each patch read is added to the patch: z + r.
  2. An MLP on each patch, then a second layer repeats the read with the same neighbours.
  3. The photo's patches join the row's cells, with a marker that says "patch".
  4. TabICL's row transformer pools cells and patches into one row vector.
  5. The in-context transformer attends row to row; the test rows' labels are predicted there.
